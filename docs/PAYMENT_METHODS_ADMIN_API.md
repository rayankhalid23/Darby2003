# توثيق API — إدارة طرق الدفع (لوحة الأدمن)

Base: `/api/admin/payment-methods` (أو `/api/v1/admin/payment-methods`)
كل المسارات تحتاج `Authorization: Bearer {token}` + صلاحية `financial.manage_payment_methods` (المدير العام يتجاوزها تلقائياً).

## ✅ تم التبسيط (2026-09-12)

بناءً على طلبك: النظام يعتمد **الدفع الفوري فقط** (`instant_simulation`) **ولولي الأمر حصراً** (`target_audience = parent`) — لا وجود لخيار "تحويل يدوي" ولا "وسيلة للسائق" بالأدمن بعد الآن. شاشتا الإضافة والتعديل صارتا تحتويان على **الأساسيات فقط**:

- أُزيل حقل `processing_type` من نموذج الإدخال — **يُثبَّت تلقائياً على `instant_simulation`** بالسيرفر، ولا يمكن لأي قيمة تُرسَل من الفرونت تغييره (اختبرته: حتى لو أُرسل `manual_proof` عمداً، يُتجاهل).
- أُزيل حقل `target_audience` من نموذج الإدخال أيضاً — **يُثبَّت تلقائياً على `parent`** لنفس السبب (لا مسار شحن فعلي للسائق يعتمد على هذا الجدول). اختبرته: حتى لو أُرسل `driver`/`both` عمداً، يُتجاهل.
- أُزيلت حقول التحويل البنكي اليدوي من نموذج الإدخال: `name_en`, `account_name`, `account_number`, `iban`, `wallet_number`, `instructions_ar`, `instructions_en`. (الأعمدة نفسها باقية بقاعدة البيانات لأي استخدام مستقبلي، فقط الأدمن لم يعد يُطالَب بتعبئتها).
- النموذج الحالي: **`name_ar` + `code` + `min_amount` + `max_amount` + `is_active` + `sort_order` + `icon`** (رفع صورة).

## ✅ أيقونة الوسيلة أُضيفت (2026-09-12، تحديث لاحق)

**نعم، الأدمن يرفع صورة/أيقونة فعلية لكل وسيلة دفع، وتظهر لولي الأمر بالفعل.** لم تكن هذه الميزة موجودة (كانت `icon_url` رابطاً نصياً يُلصق يدوياً، وأُزيلت بالتبسيط الأول) — الآن أصبحت **رفع ملف حقيقي**:

- حقل الإدخال اسمه `icon` (ملف، مو رابط نصي) — يُرسَل عبر `multipart/form-data` وليس JSON خالص.
- يُخزَّن الملف فعلياً على السيرفر (`storage/payment_methods/icons/`) ويُبنى منه رابط مباشر جاهز `icon_url` يُحفظ بقاعدة البيانات.
- **تعديل الوسيلة برفع أيقونة جديدة يحذف الملف القديم تلقائياً من القرص** (اختبرته فعلياً — لا تتراكم ملفات يتيمة).
- `icon_url` الناتج **يظهر الآن لولي الأمر** عبر `GET /parent/wallet/payment-methods` (وللسائق أيضاً لو وُجدت وسيلة تخصه مستقبلاً) — اختبرته فعلياً بعد الرفع مباشرة.

## ✅ عرض الأدمن نُظّف بالكامل (2026-09-12، تحديث ثانٍ)

`index`/`show`/`store`/`update` كانت كلها لا تزال تُرجع نموذج `PaymentMethod` الخام بكل أعمدته القديمة (`name_en`, `account_name`, `account_number`, `iban`, `wallet_number`, `instructions_ar`, `instructions_en`, `target_audience`, `processing_type`, `deleted_at`) رغم إزالتها من الإدخال بالتبسيط الأول — **الآن العرض يطابق الإدخال تماماً**، فقط: `id, name_ar, code, icon_url, min_amount, max_amount, is_active, sort_order, created_at, updated_at`.

**🐞 خطأ حقيقي وُجد وصُلح أثناء هذا التنظيف:** إنشاء وسيلة بلا تحديد `min_amount`/`max_amount`/`is_active`/`sort_order` (تعتمد على القيم الافتراضية 1.00/50000.00/true/0) كان **رد الإنشاء نفسه** يعرض قيماً خاطئة تماماً (`min_amount:0, max_amount:0, is_active:false, sort_order:null`) بينما **القيمة الفعلية المخزَّنة بقاعدة البيانات كانت صحيحة دائماً** (تحققت مباشرة من الجدول). السبب: `PaymentMethodService::create()` كان يُرجع نموذج Eloquent فور الإنشاء بدون إعادة قراءته من القاعدة، فلا يحمل القيم الافتراضية التي طبّقتها القاعدة على عمود لم يُرسَل به أي قيمة. أضفت `->fresh()` — اختبرت: الرد صار يطابق القاعدة تماماً.

- **وسائل الدفع القديمة (المختلطة manual_proof/driver) مُسحت بالكامل** وأُعيد زرعها من الصفر عبر `database/seeders/PaymentMethodSeeder.php` — بذرة مخصّصة واحدة idempotent (تشغيلها لاحقاً يمسح القديم ويعيد نفس القائمة النظيفة بلا تكرار):
  ```bash
  php artisan db:seed --class=PaymentMethodSeeder
  ```
  القائمة الحالية بعد التشغيل: `sadad`, `tadawul`, `moamalat` — كلها `target_audience=parent` و`processing_type=instant_simulation`. لإضافة وسيلة جديدة للبذرة نفسها، يكفي سطر واحد بمصفوفة `METHODS` داخل الملف.
  تحققت: قائمة السائق لوسائل الدفع (`GET /driver/wallet/payment-methods`) ترجع **فارغة** الآن بلا أي خطأ (متوقع وصحيح — العمود `payment_method_id` بطلبات شحن السائق أصلاً اختياري).

## 📋 شرح الحقول (الشاشة المبسّطة — إضافة وتعديل)

| الحقل | الغاية منه | ماذا يُدخل الأدمن |
|---|---|---|
| `name_ar` | الاسم المعروض لوسيلة الدفع بواجهة ولي الأمر | اسم واضح، مثال: `"خدمة سداد (Sadad)"` |
| `code` | **معرّف داخلي فريد** يستخدمه الكود نفسه للربط (مو للعرض) — يُستخدم بمسارات الشحن | نص إنجليزي قصير بلا مسافات، **يجب أن يبقى فريداً**. مثال: `sadad`. **لا يُغيَّر بعد الإنشاء إلا بحذر** |
| `min_amount` | أقل مبلغ شحن مسموح بهذه الوسيلة | رقم، افتراضي `1.00` لو تُرك فارغاً |
| `max_amount` | أعلى مبلغ شحن مسموح بهذه الوسيلة | رقم، افتراضي `50000.00`. **يجب أن يكون أكبر من `min_amount`** — النظام يرفض الحفظ لو ساوى أو قلّ عنه |
| `is_active` | هل الوسيلة مفعّلة وتظهر للمستخدمين حالياً؟ | `true`/`false` — افتراضي `true` |
| `sort_order` | ترتيب ظهور الوسيلة بالقائمة (الأصغر يظهر أولاً) | رقم صحيح، مثال: `1`, `2`, `3` |
| `icon` | صورة/شعار الوسيلة تظهر لولي الأمر بشاشة اختيار وسيلة الدفع | **ملف صورة** (مو رابط نصي) — jpeg/png/jpg/webp/svg، أقصى 2 ميجابايت. اختياري تماماً — بدونه تبقى `icon_url` فارغة (`null`) والفرونت يعرض أيقونة افتراضية |

**حقول للعرض فقط (يُنشئها النظام تلقائياً، تظهر بالرد لكن لا تُرسَل بالإدخال):** `id`, `icon_url` (الرابط الناتج من رفع `icon`)، `created_at`, `updated_at`.

⚠️ `target_audience` و`processing_type` و`deleted_at` **لم تعد تظهر بالرد إطلاقاً** بعد آخر تنظيف — كانت تُعرض سابقاً كـ"للعرض فقط" لكن أُزيلت لأنها بلا فائدة عملية (قيمتها ثابتة دائماً `parent`/`instant_simulation`، و`deleted_at` دائماً `null` بالسياقات العادية).

## 1. `GET /admin/payment-methods` — عرض القائمة

### Input (Query Params — كلها اختيارية)
| الحقل | النوع | الوصف |
|---|---|---|
| `is_active` | boolean | فلترة حسب التفعيل |
| `search` | string | بحث نصّي على `name_ar` و`code` |
| `per_page` | int | حجم الصفحة، افتراضي `15` |

### Output (200) — رد حقيقي بعد التنظيف
```json
{
  "status": true,
  "data": [
    {
      "id": 31,
      "name_ar": "خدمة سداد (Sadad)",
      "code": "sadad",
      "icon_url": null,
      "min_amount": 1,
      "max_amount": 5000,
      "is_active": true,
      "sort_order": 1,
      "created_at": "2026-09-12T16:04:02.000000Z",
      "updated_at": "2026-09-12T16:04:02.000000Z"
    }
  ],
  "pagination": { "current_page": 1, "last_page": 1, "total": 3, "per_page": 15 }
}
```
هذا **كل ما يرجعه الرد الآن** — لا `name_en`, لا `account_*`, لا `iban`/`wallet_number`/`instructions_*`, لا `target_audience`/`processing_type`/`deleted_at`. `icon_url` تكون `null` لو ما رفع الأدمن أيقونة.

## 2. `POST /admin/payment-methods` — إضافة وسيلة جديدة

⚠️ **`multipart/form-data` وليس JSON خالص** — لأن الطلب قد يحمل ملف صورة (`icon`). لو ما رح ترفع أيقونة بهذي المرة، أرسل باقي الحقول عادي بنفس نوع المحتوى (متصفحات/مكتبات الفرونت الحديثة تدعم هذا تلقائياً).

### Input (Body — multipart/form-data)
**كل الحقول المتاحة (مبسّطة، مع أيقونة):**
```
name_ar:    خدمة سداد
code:       sadad_v2
min_amount: 5
max_amount: 3000
is_active:  true
sort_order: 2
icon:       <ملف الصورة>
```
**أقل مثال ممكن (الحقول الإجبارية فقط، بدون أيقونة):**
```json
{
  "name_ar": "خدمة سداد",
  "code": "sadad_v2"
}
```

| الحقل | إجباري | نوع القيمة المقبول |
|---|---|---|
| `name_ar` | ✅ | نص، أقصى 100 حرف |
| `code` | ✅ | نص، أقصى 50 حرف، **فريد** (يرفض التكرار) |
| `min_amount` | اختياري | رقم، ≥ 0.5 |
| `max_amount` | اختياري | رقم، **يجب > min_amount** (وإلا 422) |
| `is_active` | اختياري | boolean |
| `sort_order` | اختياري | رقم صحيح |
| `icon` | اختياري | ملف صورة: jpeg/png/jpg/webp/svg، أقصى 2 ميجابايت |

⚠️ أي حقل آخر تُرسله الواجهة (مثل `target_audience`, `processing_type`, `account_number`, `icon_url` كنص...) **يُتجاهل بالكامل ولا يُخزَّن** — `target_audience` يُثبَّت دائماً على `parent` و`processing_type` على `instant_simulation` بغض النظر عمّا يُرسَل. **لصق رابط جاهز بحقل `icon_url` لا يعمل — لازم رفع ملف فعلي بحقل `icon`.**

### Output (201 — نجاح، مع أيقونة مرفوعة) — رد حقيقي بعد التنظيف والإصلاح
```json
{
  "status": true,
  "message": "تم إنشاء طريقة الدفع بنجاح.",
  "data": {
    "id": 38,
    "name_ar": "خدمة سداد",
    "code": "sadad_v2",
    "icon_url": "https://your-app.example/storage/payment_methods/icons/NLriLHGn...png",
    "min_amount": 5,
    "max_amount": 3000,
    "is_active": true,
    "sort_order": 2,
    "created_at": "2026-09-12T15:00:00.000000Z",
    "updated_at": "2026-09-12T15:00:00.000000Z"
  }
}
```
✅ **تحقّق مهم:** لو أرسلت الحد الأدنى للحقول فقط (`name_ar` + `code` بدون `min_amount`/`max_amount`/`is_active`/`sort_order`)، الرد الآن يعرض **القيم الافتراضية الصحيحة فعلياً** (`min_amount:1, max_amount:50000, is_active:true, sort_order:0`) — كان بها خلل يعرض `0`/`false`/`null` رغم أن المخزَّن بقاعدة البيانات كان صحيحاً دائماً؛ تم إصلاحه (`PaymentMethodService::create()`).

### أخطاء محتملة (422)
- `code` مكرر:
```json
{ "message": "The code has already been taken.", "errors": { "code": ["The code has already been taken."] } }
```
- `max_amount` ≤ `min_amount`:
```json
{ "message": "The max amount field must be greater than min amount.", "errors": { "max_amount": ["..."] } }
```

## 3. `GET /admin/payment-methods/{id}` — عرض وسيلة واحدة

### Input
`id` بالمسار فقط — لا Body.

### Output (200)
نفس شكل عنصر واحد من القائمة (القسم 1)، أو **404** لو `id` غير موجود.

## 4. `PUT /admin/payment-methods/{id}` — تعديل وسيلة موجودة

⚠️ **`multipart/form-data`** لو رح تُرفق أيقونة جديدة بنفس الطلب (PHP لا يقرأ ملفات مع `PUT` مباشرة من بعض العملاء — لو واجهت مشكلة، أرسلها بصيغة `POST` مع حقل خفي `_method=PUT`، أسلوب Laravel القياسي لمحاكاة PUT مع رفع ملفات).

### Input (Body)
**كل الحقول اختيارية (تعديل جزئي)** — أرسل فقط الحقول التي تريد تغييرها:

| الحقل | القيم المقبولة |
|---|---|
| `name_ar` | نص، أقصى 100 حرف |
| `code` | نص فريد (باستثناء نفس السجل) |
| `min_amount` | رقم |
| `max_amount` | رقم |
| `is_active` | boolean |
| `sort_order` | رقم صحيح |
| `icon` | ملف صورة جديد (jpeg/png/jpg/webp/svg، أقصى 2MB) — **يستبدل الأيقونة الحالية ويحذف الملف القديم تلقائياً من السيرفر** (اختبرته فعلياً) |

**مثال — تعديل الحد الأقصى فقط:**
```json
{ "max_amount": 8000 }
```

⚠️ `processing_type` و`target_audience` غير مقبولَين إطلاقاً بهذا المسار حتى لو أُرسلا — تبقى الوسيلة `instant_simulation`/`parent` دائماً (اختبرته فعلياً). **لا يوجد حقل لحذف الأيقونة بلا استبدال** — لو تحتاج إزالتها نهائياً بدون رفع بديل، قلّي وأضيفها.

### Output (200)
```json
{
  "status": true,
  "message": "تم تعديل طريقة الدفع بنجاح.",
  "data": { "...": "نفس شكل عنصر القسم 1 بعد التعديل" }
}
```

### خطأ خاص بهذا المسار (422)
لو نتيجة دمج القيمة المُرسلة مع القيمة القديمة بقاعدة البيانات تجعل `min_amount ≥ max_amount`:
```json
{
  "status": false,
  "message": "الحد الأدنى للمبلغ يجب أن يكون أقل من الحد الأقصى.",
  "errors": { "max_amount": ["يجب أن يكون الحد الأقصى أكبر من الحد الأدنى."] }
}
```

## 5. `PATCH /admin/payment-methods/{id}/toggle-status` — تفعيل/تعطيل سريع

عكس حالة `is_active` الحالية مباشرة بدون أي مدخلات.

### Input
لا Body — فقط `id` بالمسار.

### Output (200)
```json
{
  "status": true,
  "message": "تم تغيير حالة تفعيل وسيلة الدفع بنجاح.",
  "data": { "id": 5, "name_ar": "خدمة سداد", "is_active": false }
}
```

---

## 6. `DELETE /admin/payment-methods/{id}` — حذف وسيلة

حذف ناعم (Soft Delete) — يختفي من القائمة لكن يبقى بقاعدة البيانات.

### Input
لا Body — فقط `id` بالمسار.

### Output (200)
```json
{ "status": true, "message": "تم حذف طريقة الدفع بنجاح." }
```
لا يوجد مسار "استرجاع" (`restore`) متاح حالياً من لوحة الأدمن.

## ملاحظات مهمة للفرونت

1. **احذف حقول التحويل اليدوي من شاشة الإضافة/التعديل بالواجهة** (اسم الحساب، رقم الحساب، IBAN، رقم المحفظة، التعليمات، الاسم الإنجليزي) — لم تعد جزءاً من تدفق العمل، والسيرفر يتجاهلها حتى لو أُرسلت. **الأيقونة مستثناة من هذا البند** — أعيدت كحقل رفع ملف فعلي (`icon`)، أبقِها بالواجهة.
2. **شاشتا الإضافة والتعديل يجب أن تُرسلا `multipart/form-data`** الآن (مو JSON خالص) — بسبب حقل `icon`. حتى لو المستخدم ما اختار صورة، أرسل باقي الحقول بنفس نوع المحتوى.
3. لا داعي لعرض اختيار "نوع المعالجة" (فوري/يدوي) بالواجهة إطلاقاً — كل وسيلة تُنشأ فورية تلقائياً.
4. `min_amount`/`max_amount` بالـ Output تُرجَع كنص عشري (`"5.00"`) — حوّلها بالفرونت قبل أي مقارنة حسابية.
5. `code` هو مفتاح الربط الفعلي بالنظام — أي شاشة إنشاء يجب أن توضّح للأدمن أنه معرّف تقني ثابت (يُفضَّل تقييده بالفرونت لحروف إنجليزية صغيرة و`_` فقط).
6. `icon_url` تكون `null` لو ما رفع الأدمن أيقونة — اعرض أيقونة افتراضية عامة بالفرونت بدل حقل فارغ (لولي الأمر وبلوحة الأدمن).
