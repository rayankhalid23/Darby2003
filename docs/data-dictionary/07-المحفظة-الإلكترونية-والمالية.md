# 07 — المحفظة الإلكترونية والبيانات المالية

يعتمد النظام على حزمة **bavix/laravel-wallet** (`Bavix\Wallet\Traits\HasWallet`) على كل من موديل `User` وموديل `Driver`، أي أن كلاً من ولي الأمر والسائق لديه محفظة مستقلة عبر علاقة متعددة الأشكال (Polymorphic). الرصيد يُخزَّن بأصغر وحدة عملة (فلس/قرش)، ويُعرض بعد القسمة على 100.

## جداول الحجز المالي (Escrow) والتسوية

تدير دورة "التكلفة التقديرية ← الحجز ← التسوية النهائية".

### `financial_ledger` (سجل حركات غير قابل للتعديل)

transaction_id (uuid), reference_number, source_account, destination_account, amount (bigint — بأصغر وحدة), balance_before/after, type (recharge / trip_hold / trip_capture / driver_payout / withdrawal_cash / penalty / compensation / platform_commission ...), status (افتراضي 'completed'), metadata (json).

### `master_escrow_vault` (خزينة مركزية — صف واحد)

parents_escrow_pool, driver_pending_pool, driver_available_pool, platform_revenue_pool, penalty_pool (جميعها bigint).

### `trip_escrow_holds`

trip_id (FK trips), parent_id, driver_id, amount (bigint), hold_status (افتراضي 'held': held / captured_pending / released_available / disputed / refunded / partially_refunded), held_at / captured_at / available_at / disputed_at.

### `trip_disputes`

trip_id (FK trips), parent_id, driver_id, reason (text), status (افتراضي 'open': open / resolved_parent_refunded / resolved_driver_paid / rejected), resolution_notes, resolved_by, resolved_at.

### استخدام هذه الكيانات في وظائف التطبيقين

- **عرض رصيد المحفظة** (ولي الأمر والسائق): قراءة `wallets.balance` عبر `->balance` (bavix trait) بعد القسمة على 100.
- **شحن المحفظة** (ولي الأمر): إنشاء `recharge_requests` مرتبط بـ `payment_methods`، ثم عند التأكيد يُضاف رصيد إلى `wallets` وتُسجَّل حركة في `transactions`.
- **إلغاء الاشتراك** (كلا التطبيقين): يُحدَّث `platform_finances.status` ويُسجَّل استرداد في `financial_ledger`/`trip_escrow_holds` وفق سياسة الإلغاء (انظر [05](05-الاشتراكات-الحالية.md)).
