# 09 — البحث عن سائق والتسعير التقديري

## 1. البحث المباشر / البحث بناءً على بيانات الأطفال / التصفية

**الخدمة:** `app/Services/Parent/DriverMatchingService.php` — **المتحكم:** `app/Http/Controllers/Api/Parent/DriverSearchController.php` — **التحقق من المدخلات:** `app/Http/Requests/Api/Parent/SearchDriversRequest.php`

### معايير البحث/التصفية المُدخلة (وليست أعمدة قاعدة بيانات، بل مدخلات الطلب)

| المعيار | القيم | ملاحظات |
|---|---|---|
| search_query / query / keyword / name / phone | نص حر | يُطابق `users.full_name`/`phone_number`/`alternative_phone`، مع تطبيع الهمزات العربية ومطابقة الأرقام فقط |
| driver_gender | male / female / both | يقابل `drivers.accepted_gender` |
| has_ac | boolean | يقابل `vehicles.has_ac` مع `vehicles.status = 'Active'` |
| child_ids[] | معرّفات | يجب أن تخص `children.parent_id` لولي الأمر المسجّل دخوله |
| start_date / end_date | تاريخ | افتراضي نفس اليوم إن لم تُحدَّد؛ end_date ≥ start_date |
| trip_direction | go / return / both | يقابل `requests.trip_direction` لاحقًا |
| subscription_type | single_day / multi_day | يقابل `requests.subscription_type` لاحقًا |

### خط أنابيب المطابقة (`matchDrivers`)

1. **استعلام أساسي:** `drivers.status IN ('Approved','Active')`، `users.is_trusted = true`، `license_expiry >= اليوم`.
2. **إن وُجد نص بحث حر** → مطابقة على `users.full_name`/`phone_number`/`alternative_phone` فقط (تُتجاوز بقية معايير التصفية).
3. **بخلاف ذلك تُطبَّق التصفيات التالية بالترتيب:**
   - **تصفية الجنس:** `drivers.accepted_gender` (تُتجاوز إذا كانت القيمة المطلوبة `'both'`، لأن `users.gender` لا يملك قيمة `'both'`).
   - **تصفية التكييف:** `vehicles.status = 'Active' AND has_ac`.
   - **تصفيات ذكية للأطفال** (فقط عند إرسال `child_ids`):
     - **توافق الجنس:** مطابقة `drivers.accepted_gender` مع مزيج أجناس الأطفال المحددين.
     - **توفر المقاعد:** استبعاد السائقين الغائبين (`driver_absences` بحالة pending/approved) خلال فترة البحث؛ يجب تفعيل علم الفترة المطلوبة لدى السائق (`drivers.morning_go`/إلخ)؛ فحص السعة الفعلية عبر استعلام على `driver_seat_slots` (السعة `vehicles.capacity_manual` ناقص الحجوزات القصوى ≥ العدد المطلوب، باستثناء الجمعة والسبت).
     - **تصفية المنطقة الجغرافية:** يجب أن يغطي السائق (عبر `driver_zone`) **جميع** مناطق (`zones`) مدارس/عناوين الأطفال المحددين.
4. **الترتيب:** تنازليًا حسب `drivers.rating_avg`، تقسيم صفحات كل 15 نتيجة.
5. لكل سائق مطابق تُحسب التكلفة التقديرية فوريًا (`calculatePricingForDriver`) — القيم الناتجة (`estimated_total_price`, `pricing_breakdown`, `platform_fee`, `driver_net_amount`) **محسوبة وقت الطلب وليست أعمدة مخزّنة**.

> ملاحظة: يوجد أيضًا `app/Http/Controllers/Api/Driver/DriverRecommendationController.php` (ملف جديد غير مُرحَّل ضمن git) وهو غلاف رفيع يستدعي سكربت بايثون (`python/predict.py`) لإعادة ترتيب قائمة سائقين مُرسَلة مسبقًا بالذكاء الاصطناعي، ولا يستعلم قاعدة البيانات مباشرة — لا علاقة له ببحث ولي الأمر عن سائق.

## 2. عرض التكلفة التقديرية لطلب الاشتراك

**الخدمة المرجعية:** `app/Services/Shared/PricingCalculator.php::calculateForChild()` (يُعاد استخدام نفس المنطق داخل `DriverMatchingService::calculatePricingForDriver()` أثناء عرض نتائج البحث، بحيث يرى ولي الأمر نفس الرقم في مرحلتي البحث والطلب).

### جدول `pricing_settings` (سجل إعدادات واحد غالبًا)

**المصدر:** `migrations_v2/2026_09_04_100016` + تمديدات `2026_08_28_001024`, `001453`, `2026_08_31_000001`.

| الحقل | النوع | القيمة الافتراضية | الوصف |
|---|---|---|---|
| price_per_km_ac | decimal | 2.50 | سعر الكيلومتر للمركبات المكيّفة |
| price_per_km_non_ac | decimal | 2.00 | سعر الكيلومتر لغير المكيّفة |
| discount_one_child | decimal | 0.00 | خصم عند طفل واحد |
| discount_two_children | decimal | 10.00 | خصم عند طفلين |
| discount_three_plus_children | decimal | 15.00 | خصم عند 3 أطفال فأكثر |
| platform_commission_rate | decimal | 8.00 | نسبة عمولة المنصة |
| location_change_fee (+ فئات: `_under_2km`, `_2_to_6km`, `_6_to_10km`) | decimal | — | رسوم تغيير الموقع حسب المسافة |

### صيغة الحساب

```
المسافة الفعلية = max( المسافة بين عنوان الطفل والمدرسة (OSRM أو Haversine احتياطيًا) , 4.0 كم )
سعر الرحلة (اتجاه واحد) = المسافة الفعلية × سعر الكيلومتر (حسب تكييف المركبة)
السعر اليومي = سعر الرحلة × عدد الرحلات يوميًا (1 أو 2 حسب trip_direction)
الإجمالي الخام = السعر اليومي × عدد أيام العمل (أيام الأسبوع فيما عدا الجمعة والسبت، أو 1 ليوم واحد)
قيمة الخصم = الإجمالي الخام × نسبة الخصم الجماعي / 100
الإجمالي بعد الخصم = الإجمالي الخام − قيمة الخصم
عمولة المنصة = الإجمالي بعد الخصم × نسبة العمولة / 100
صافي مستحقات السائق = الإجمالي بعد الخصم − عمولة المنصة
```

### المدخلات المسحوبة من قاعدة البيانات

- `pricing_settings` (الأسعار والخصومات ونسبة العمولة).
- `vehicles.has_ac` (من مركبة السائق النشطة) — لتحديد سعر الكيلومتر (مكيّف/غير مكيّف).
- `children.gender` — لتحديد شريحة الخصم الجماعي (حسب `children_count`).
- إحداثيات `children.address` (عبر `addresses`) و`children.school` (عبر `schools`) — لحساب المسافة.
- `trip_direction` (go/return/both) و`subscription_type` (single_day/multi_day) و`start_date`/`end_date` — لتحديد عدد الرحلات اليومية وعدد أيام العمل.

### أين تُخزَّن نتيجة الحساب لاحقًا؟

عند إرسال طلب الاشتراك فعليًا، تُحفظ لقطة من نتائج هذا الحساب في أعمدة جدول `requests` (`total_price`, `discount_amount`, `total_amount_after_discount`, `price_per_km`, `vehicle_has_ac`, `discount_percent`, `platform_commission_rate`, `platform_commission_amount`, `driver_net_amount`, `working_days_count`) وجدول `request_children` (تفصيل لكل طفل) — انظر [04-طلبات-الاشتراك.md](04-طلبات-الاشتراك.md).
